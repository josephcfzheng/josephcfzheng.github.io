部署流程（6 步完成）

1

创建 GitHub 仓库

在 GitHub 上新建一个公开或私有仓库。仓库名将成为你的子域名。

# 推荐：使用你的用户名 + .github.io 作为仓库名
# 例如：username.github.io

# 或任意仓库名，启用 Pages 后访问路径为：
# https://username.github.io/repository-name/
2

克隆仓库到本地

将远程仓库克隆到本地工作目录。

git clone https://github.com/YOUR_USERNAME/your-repo.git
cd your-repo
3

放置 HTML 文件

将你的 HTML 文件放入仓库根目录（或 docs/ 目录）。

ⓘ 注意：主页必须命名为 index.html，否则 GitHub Pages 无法自动识别入口文件。

4

推送代码到远程

提交并推送文件到 GitHub。

git add .
git commit -m "Initial deployment"
git push origin main
5

启用 GitHub Pages

在仓库的 Settings → Pages 页面：

  • Source 选择 Deploy from a branch
  • Branch 选择 main，根目录 / (root)
  • 点击 Save

✅ 完成：等待 1-2 分钟，你的网站将可通过 https://username.github.io/repository-name 访问。

6

（可选）绑定自定义域名

购买域名后（推荐 Namecheap，约 $9/年），在仓库设置中添加：

# 1. 在仓库根目录创建 CNAME 文件
echo "yourdomain.com" > CNAME

# 2. 推送 CNAME 文件
git add CNAME
git commit -m "Add custom domain"
git push

# 3. 在 Settings → Pages → Custom domain 填入域名

同时在域名注册商处添加一条 CNAME 记录：username.github.io

常用命令速查

使用 gh CLI（推荐）

# 创建仓库并启用 Pages
gh repo create username.github.io --public --enable-pages

# 克隆并推送
gh repo clone username.github.io
cd username.github.io
# ... 放入 HTML ...
git add . && git commit -m "deploy" && git push

# 查看部署状态
gh api repos/username/username.github.io/pages/builds --jq '.[].status'

使用纯 git（无 gh）

# 初始化裸仓库（已有文件时）
git init
git remote add origin https://github.com/username/repo.git
git add . && git commit -m "init"
git push -u origin main

# 更新部署
git add . && git commit -m "update" && git push

常见问题

Q: 部署后页面是空白？
A: 检查 index.html 是否在根目录，以及相对路径引用是否正确。GitHub Pages 的路径前缀是仓库名。

Q: 多久能生效？
A: 通常 1-2 分钟。可点击 Pages 设置中的 "Build and deployment" 查看构建日志。

Q: 可以部署多个项目吗？
A: 可以。每个项目一个仓库，每个仓库独立启用 Pages。
